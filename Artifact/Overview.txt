The artifact is a prototype for approximate parallel DBSCAN using locality sensitive hashing.

Software Requirements
We bench-marked the artifact on a fresh installation of Ubuntu 20.04 on Amazon Web Services
using a c5.18xlarg machine. The software dependencies are GSL (GNU Scientific Library), TBB
(Threading Building Blocks), POSIX pthreads, and GOMP. Below shows the installed version of
the aforementioned libraries on the Amazon machine which we used for bench-marking.

In addition to the aforementioned libraries, we utilized a third-party software to compute the rand
index accuracy of our method in comparison with exact DBSCAN algorithms (e.g., references
[13,22,31] in the manuscript). The source of the third party software that we use to calculate the
rand index values can be found in the following git repository:
https://github.com/bjoern-andres/partition-comparison.git
For our convenience, we adapted the aforementioned software to create a command line tool as the
following:
./computeAccuracy_fast [index_file_1] [index_file_2] [output_file]
Where index_file_1 and index_file_2 are two files containing line-separated clustering indexes
created by approximate and exact algorithms (the order is not important). The corresponding rand
index value will be added as a new line at the end of output_file.
We use the aforementioned command line tool to calculate the rand index accuracy of our
experiments. We attach the adapted project for your convenience, but you are more than welcome to
use the original software given in the aforementioned git repository or any other software that can
calculate rand index accuracy.

How to Build
Navigate to project’s root folder (where CmakeLists.txt exists), and issue the following commands:
mkdir build; cd build; cmake ..; make -j

A successful build will lead to creation of 4 executable binaries:
1. Vanila_DBSCAN_exec: This is our implementation of plain exact sequential DBSCAN
algorithm.
2. Vanila_DBSCAN_LSH_exec: This is our implementation of approximate sequential
DBSCAN algorithm proposed in references [25,34], where the idea is to use LSH for
epsilon queries (see the manuscript).
3. ParameterExploration_exec: This binary executes IP.LSH.DBSCAN with varying
parameters and logs the accuracies.
4. LSHDBSCAN_exec: This binary is the IP.LSH.DBSCAN algorithm. It can be executed as
a command line.

Usage
LSHDBSCAN_exec can take several parameters:
1. -f inputFile: inputFile is the full address and the file name of the dataset to cluster. Each row
in the dataset must correspond to one observation (one point). Different features (i.e.,
dimensions) for each observation must be separated by space.
2. -L #HashTables: We can set the number of LSH tables with this parameter (check the
manuscript).
3. -M #HashFunctionsPerTable: We can set the number of hash functions per table with this
parameter (check the manuscript).
4. -t #threads: We can set the number of threads with this parameter.
5. -e eps: We can set the epsilon value (DBSCAN’s parameter) with this parameter.
6. -m minPts: We can set the minPts value (DBSCAN’s parameter) with this parameter.
7. -b baselineClusteringFile: We can choose the baseline (exact) clustering index file with this
option to calculate the clustering accuracy (which will be concatenated at the end of a file
named accuracy.txt).
8. -a: This option does not require a value. If set, the algorithm utilizes the angular distance;
otherwise, the algorithm uses Euclidean distance by default.
Each time LSHDBSCAN_exec finishes clustering, it appends its execution log as a line at the end
of a file named benchmark.txt. Execution log consists of duration of different phases of the
algorithm. Therefore, one way to calculate how long each execution takes is to sum up the
corresponding entries added in the benchmark.txt file.

Bench-marking IP.LSH.DBSCAN
Benchmarked datasets (and their clustering indexes using exact DBSCAN with manuscript’s
defaults parameters) can be found in the following link:
https://drive.google.com/drive/mobile/folders/12pflqbkR8PuhvW_9dkuRqa2kQ0GSV-KE?usp
%5C=sharing
Navigate to the benchmarks folder. Firstly, make sure the copy of computeAccuracy_fast binary
(see §Software Requirements) is executable (or build the binary yourself). In this folder,
script_LSHDBSCAN_general.sh is the key to replicating the manuscript’s results. For each
dataset, there is a line. Simply uncomment the desired line and make sure the lines corresponding to
other datasets are commented. For example, the configuration in the attached screenshot will run
IP.LSH.DBSCAN on the household dataset with epsilon=2000, minPts=100, L=20, M=5, which
corresponds to the yellow plot in Fig. 3 (b) in the manuscript. After bench-marking with the
aforementioned parameters are completed, the script will rename the files. Repeat the process with
{L=10, M=5}, and {L=5, M=5} (keep epsilon and minPts unchanged) to gather the results
corresponding to the dark blue and orange plots in Fig. 2 (b). The remainder of the results in Fig.
2(b) correspond to the other bench-marked methods (competitors) which can be obtained as open
source software. Once all the data is gathered, use the attached Matlab script
(completionTimes_EuroPar.m) to plot the results. Make sure the measurements are organized into
folders with the following hierarchy:
amazon
household
LSHDBSCAN
TEDBSCAN
HPDBSCAN
PDSDBSCAN

Note. For convenience, three dedicated script files are provided in the benchmarks folder to
replicate the IP.LSH.DBSCAN results in Fig. 3 (a), Fig. 3 (b), and Fig. 3 (c) of the manuscript.

Bench-marking Competitors
TEDBSCAN
TEDBSCAN abbreviates Theoretically-Efficient and Practical Parallel DBSCAN [1].
Link to source code: https://github.com/wangyiqiu/dbscan-python
Commit version: be4871c
Important Notes: Make sure the format of the input dataset to this algorithm is compatible with the
requirements of its implementation. For example, the implementation of this algorithm silently
discards data points containing non-decimal values (for example when the values are represented in
scientific format). Furthermore, the following line must appear on the first line of the input dataset:
dim [number of dimensions of the input dataset]
HPDBSCAN
HPDBSCAN abbreviates Highly parallel DBSCAN [2].
Link to source code: https://github.com/Markus-Goetz/hpdbscan
Commit version: ae0c74c
Notes: The implementation of this algorithm requires the data to be presented in h5 format.
PDSDBSCAN
PDSDBSCAN refers to a new scalable parallel DBSCAN algorithm using the disjoint-set data
structure [3].
Link to source code: http://users.eecs.northwestern.edu/~mpatwary/Software.html
